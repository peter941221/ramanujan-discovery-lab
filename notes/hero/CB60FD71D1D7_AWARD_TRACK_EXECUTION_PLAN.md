## First Deep-Research Pass (`2026-03-18`)

This pass focuses on the literature gap that most directly affects the next
coding move.

### Main finding

The current local scans already cover many direct / reciprocal / quotient /
power ladders, but the literature says the `GG` orbit is controlled by
structured nonlinear modular relations that are **not** yet encoded directly.

### Source-driven conclusion

The next local recognition lane should be:

```text
GG modular-equation / substitution lane
with explicit variables for
H(q), H(-q), H(q^2), H(q^3), H(q^4)
and modular-equation descendants of odd prime degree
```

### Why this is the right next move

1. Chan--Huang (1997) does not treat `GG` as only a product object.
   It derives identities linking `H(q)` with `H(-q)` and `H(q^2)`, and then
   explains how modular equations yield relations between `H(q)` and `H(q^n)`,
   with explicit attention to the `q^3` and `q^4` lanes.
2. Cho--Koo--Park (2009) upgrades that same orbit from isolated identities to a
   modular-function / modular-unit object with odd-prime modular equations.
3. Yuttanan (2012) shows that even more structure survives in coefficient and
   evaluation behavior, so the `GG` orbit should not be treated as exhausted by
   simple multiplicative or quotient scans.

### Immediate implementation implication

Do **not** start by widening the generic basis catalog again.

Instead:

- encode a small, explicit, source-faithful `GG` modular-equation template lane
- preserve signs and substitutions explicitly
- allow `H(q)`, `H(-q)`, `H(q^2)`, `H(q^3)`, `H(q^4)` as first-class objects
- only then consider higher odd-prime modular descendants if the base lane
  still misses
